# 13번 별빛 관측 연구소 · 첫 화면 로딩 개선

첫 화면과 인트로는 지도·관측 모듈 없이 열린다. 지도에 들어가면 지도 코드와 숲 그림·캐릭터 자료를 받고, 관측실에 들어가면 관측 코드와 활동 전용 스타일을 받는다. 첫 화면의 글꼴은 기존 글꼴을 유지하되 HTML에서 미리 받지 않고 스타일이 필요할 때 요청한다. 저장된 관측실에서 이어 할 때는 지도를 거치지 않는다.

지도 코드 또는 지도 자료를 받지 못하면 **다시 열기**와 **첫 관측 시작**을 표시한다. 진행 중인 기록이 있으면 현재 열려 있는 다음 관측실을 안내한다. 지도 코드 재시도는 브라우저에서 실패한 모듈 요청을 다시 할 수 있도록 새로고침하고, 지도 자료만 실패했을 때는 지도만 다시 연다. 코드 요청은 10초, 지도 자료는 20초가 지나도 끝나지 않으면 실패 안내를 표시한다.

## 전후 비교

변경 직전과 적용 후의 Vite 프로덕션 빌드를 같은 Mac의 로컬 서버에서 비교했다. Chrome 1280×800, 캐시를 끈 새 브라우저 세션에서 빌드별·조건별 5회씩 번갈아 측정한 중앙값이다. 느린 환경은 다운로드 10 Mbps, 지연 40 ms, CPU 4배 감속을 적용했다.

| 지표 | 로컬 전 → 후 | 느린 환경 전 → 후 |
| --- | ---: | ---: |
| 접속 → 시작 버튼 조작 가능 | 35 → 38 ms | 389 → 255 ms |
| 첫 내용 표시(FCP, 초기 안내 포함) | 56 → 24 ms | 404 → 196 ms |
| 첫 화면 주요 콘텐츠 표시(LCP) | 56 → 56 ms | 808 → 696 ms |
| 인트로 종료 → 지도 준비 | 72 → 105 ms | 1,882 → 1,948 ms |
| 지도에서 관측실 선택 → 첫 관측 조작 화면 | 31 → 47 ms | 60 → 126 ms |

첫 화면에 필요한 JS는 196.67 → 125.82 kB(−36%, gzip 73.39 → 46.77 kB), CSS는 193.17 → 158.89 kB(−18%, gzip 39.65 → 34.74 kB)다. 브라우저 요청 기록에서 첫 화면에는 지도·관측 코드와 지도 자료가 없었고, 지도에서도 관측 코드가 요청되지 않았다. 첫 진입에 필요한 코드를 나중에 받으므로 지도와 관측 전환에는 시간이 추가된다. 이 수치는 운영 서버나 실제 교실 네트워크의 측정값이 아니다.

## 확인한 흐름

- 정상: 인트로를 끝까지 진행하고 지도에서 달 관측실에 들어갔다.
- 지도 JS와 지도 그림을 각각 차단: 차단을 풀고 **다시 열기**를 눌러 지도가 복구됐고, 차단을 유지한 별도 실행에서도 **첫 관측 시작**으로 들어갔다.
- 지도 차단을 유지한 상태에서 휴대폰 크기의 화면으로 달의 위치·초점·배율을 조절하고 1.5배와 2배 사진을 찍었다. 새로고침해도 관측실과 두 사진이 복원됐다.
- 관측 JS만 차단한 경우에도 차단 해제 후 **다시 열기**로 원래 관측실에 들어갔다. 지도 요청 중 홈으로 이동해도 늦게 끝난 요청이 화면을 바꾸지 않았다.
- 지도 JS 응답과 지도 스프라이트 정보 응답을 각각 보류했을 때 약 10.3초, 20.4초 뒤에 실패 안내가 떴고 첫 관측으로 이동할 수 있었다.
- 프로덕션 빌드, 단위 테스트 128개, `git diff --check`를 통과했다. 운영 주소는 유지했고 배포하지 않았다.
