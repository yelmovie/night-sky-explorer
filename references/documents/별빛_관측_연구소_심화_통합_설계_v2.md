# 0. 이번 심화 설계에서 확정하는 핵심 원칙

이 단원은 **“밤하늘 퀴즈 10개”가 아니라, 고장 난 관측 연구소의 데이터 시스템을 학생이 실제 관측과 과학적 판단으로 복구하는 게임**으로 설계한다.

학생의 최종 경험은 다음이어야 한다.

> “달 이름과 행성 이름 문제를 풀었다.”

가 아니라

> **“내가 달을 관측하고, 시간에 따른 변화를 기록하고, 행성을 조사하고, 별과 행성을 증거로 구분하고, 북극성 주변 별자리를 관찰해서 연구소의 관측 시스템을 복구했다.”**

# 1. 핵심 화면 수 정책

## 1.1 핵심 학습 화면은 정확히 10장

본 단원의 핵심 학습 화면은 **5 Stage × Stage당 2화면 = 총 10화면**으로 고정한다.

| Stage | Mission | Screen A | Screen B |
|---|---|---|---|
| 1 | 달 표면 관측 | 01 달 포착 | 02 달 표면 분석 |
| 2 | 달빛 시간 기록 | 03 여러 날 관찰 | 04 달 변화 예측 |
| 3 | 태양계 연구 | 05 미확인 행성 분석 | 06 태양계 모형 제작 |
| 4 | 별빛 판별 | 07 별·행성 비교 관측 | 08 증거 기반 분류 |
| 5 | 별자리 관찰 | 09 북극성 주변 관찰 | 10 별자리 패턴 기록 |

## 1.2 10화면 밖의 공통 메타 화면

다음 요소는 **새로운 학습 페이지로 계산하지 않고 Science World 공통 Shell / Modal / Overlay / Ending Layer**로 처리한다.

- World Incident 인트로
- Mission Map
- Research Kit
- 저장하기 / 이어하기
- Final Report
- Final Mission
- Final Movie
- Mission Complete
- 인증서 출력
- Bonus Quest 진입

즉, **핵심 학습 화면 10장 구조를 깨지 않으면서** 게임의 시작과 엔딩 경험을 강화한다.

# 2. 4학년 교육과정 범위

본 게임의 핵심 학습은 아래 세 성취기준 범위 안에서 설계한다.

## [4과13-01]
**달의 모양과 표면, 달의 위상변화를 관찰하여 밤하늘 관찰에 흥미를 가질 수 있다.**

게임 반영:
- 망원경으로 달 포착
- 달 표면 확대·비교
- 여러 날의 달 모양 변화 관찰
- 관측 결과를 바탕으로 다음 모습을 예상
- 예상과 실제 관측 자료 비교

## [4과13-02]
**태양계 구성원을 알고, 태양과 행성을 조사할 수 있다.**

게임 반영:
- 행성 3D 관찰
- 색, 줄무늬, 고리, 표면에서 보이는 특징 조사
- 관측 증거를 이용한 행성 판별
- 태양과 8개 행성을 이용한 학습용 태양계 모형 구성

## [4과13-03]
**별의 정의를 알고, 북극성 주변의 별자리를 관찰할 수 있다.**

게임 반영:
- 별과 행성의 관측 자료 비교
- 별은 스스로 빛을 내는 천체라는 핵심 정의
- 북극성 주변 별 배열 관찰
- 학생이 먼저 패턴을 기록한 후 기준 별자리 레이어와 비교

# 3. 교육과정 가드레일

## 본편 핵심 평가에서 제외

- 달 위상 변화의 원인을 태양-지구-달의 위치 관계로 설명하기
- 달의 자전·공전 원리
- 지구에서 달 뒷면이 보이지 않는 이유
- 태양·지구의 자전 방향 암기
- 음력 날짜 암기 중심 문제
- 행성의 정확한 질량·지름·거리·공전주기 계산
- 북두칠성·카시오페이아자리 등을 이용해 북극성을 찾아내는 상위 학년식 추론
- 계절별 별자리 변화 원리
- 제임스 웹 우주망원경의 적외선 원리를 본편 필수 평가로 사용

## 과학적 표현 주의

- 밤하늘 자체가 고장 난 것으로 표현하지 않는다.
- **고장 난 것은 ‘연구소의 관측 데이터 시스템’**이다.
- 달·행성·별자리의 실제 현상이 마법 때문에 바뀌었다고 표현하지 않는다.
- 태양계 모형은 **“학습용 모형 — 실제 크기와 거리 비율이 아님”**을 명확히 표시한다.
- 별자리 연결선은 사람이 별의 배열을 이해하기 위해 덧붙인 표현으로 다룬다.
- 별과 행성 구분은 **“별은 스스로 빛을 냄 / 행성은 스스로 빛을 내지 않음”**을 가장 중요한 근거로 사용한다.
- “별은 무조건 깜빡이고 행성은 절대 깜빡이지 않는다”, “색만 보면 판별할 수 있다”와 같은 지나친 단순화는 핵심 판별 규칙으로 사용하지 않는다.

# 4. 기존 설계 진단

## 4.1 유지할 강점

1. **달 → 달 변화 → 행성 → 별/행성 → 별자리**의 교육과정 흐름이 좋다.
2. 5 Stage, 10화면 구조가 명확하다.
3. 터치·드래그·핀치·시간 슬라이더·3D 회전·스캔·선 연결 등 태블릿 상호작용의 종류가 다양하다.
4. Stage 3의 3D 행성 조사와 태양계 모형 제작은 디지털 매체의 장점이 분명하다.
5. 달 변화 화면의 `관찰 → 예상 → 실제 비교` 구조가 과학 탐구에 적합하다.
6. 별자리 화면의 `먼저 관찰 → 패턴 기록 → 기준 레이어 비교` 구조가 단순 정답 맞히기보다 우수하다.

## 4.2 강화할 부분

기존 설계는 개별 화면의 상호작용은 좋지만 **좋은 활동 5개가 나란히 놓여 있는 구조**가 될 위험이 있다.

이를 다음처럼 연결한다.

```text
연구소 관측 데이터 이상 발생
↓
Mission 1 달 표면 시스템 복구
↓
Mission 2 시간 기록 시스템 복구
↓
Mission 3 태양계 데이터베이스 복구
↓
Mission 4 천체 판별 시스템 복구
↓
Mission 5 별자리 관측 지도 복구
↓
5개 Evidence를 NPC에게 전달
↓
Final Mission으로 중앙 관측 코어 재가동
↓
천문 돔 개방
```

## 4.3 학습지형 위험 요소와 개선

- 달 표면 특징 설명 카드 읽기 → **학생 관찰자료를 먼저 만들고 비교**
- 태양계 순서 Drag → **앞 화면 Evidence를 다시 호출해 구성**
- 별/행성 완성 비교표 → **관찰 Evidence에서 공통점·차이점 생성**
- 별자리 따라 그리기 → **별자리 선 없이 먼저 관찰 후 패턴 기록**
- 객관식 Final → **자기 Evidence를 중앙 코어에 직접 적용**

# 5. 단원 메인 퀘스트

## 사건 — 관측 기록이 서로 맞지 않는다

별빛 관측 연구소의 중앙 관측 코어에 오류가 발생했다.

밤하늘 자체에는 문제가 없지만 연구소 내부의 다섯 기록 시스템이 서로 다른 데이터를 보내고 있다.

- 달 표면 영상은 초점 정보가 사라짐
- 여러 날의 달 관측 기록이 끊김
- 행성 데이터의 이름표가 뒤섞임
- 별·행성 판별 기록이 연결되지 않음
- 북극성 주변 별자리 기준 레이어가 비활성화됨

중앙 천문 돔은 **검증된 연구 데이터 5종**이 모두 모이기 전에는 열리지 않는다.

## 학생 역할

학생은 **신입 별빛 관측 연구원**이 된다.

학생은 정답을 맞히는 사람이 아니라 관측하고, 확대하고, 비교하고, 기록하고, 예상하고, 검증하고, 증거를 연결하고, 다시 수정하는 연구원의 역할을 수행한다.

## 최종 목표

5개의 관측 Evidence를 복구한 뒤 중앙 관측 코어에 적용하여 **별빛 관측 연구소의 천문 돔과 데이터 시스템을 정상화한다.**

# 6. 캐릭터 시스템

## 절대 규칙

**부엉이와 로봇 캐릭터는 사용하지 않는다.**

사용자가 별도로 명시적으로 요청하는 경우에만 예외적으로 생성할 수 있다.

## 6.1 달토끼 기록원

역할:
- 학생의 관측 기록 관리
- Research Kit 담당
- 달 관련 Mission의 보조 안내
- 학생이 획득한 Evidence 보관
- 관측 결과 되돌아보기 지원

행동:
- 관측사진을 노트에 붙임
- 이전 기록을 열어 줌
- 학생의 예상과 실제 결과를 나란히 보여 줌

장식 캐릭터가 아니라 **기록 시스템의 시각적 화신**으로 사용한다.

## 6.2 별여우 연구관

역할:
- 사건 의뢰
- Mission 해금
- 증거 기반 질문
- Final Report 검토
- Final Mission 실행 안내

행동:
- 학생이 가져온 Evidence를 하나씩 확인
- 새로운 관측 구역 활성화
- 잘못된 판단 시 정답을 말하지 않고 어떤 증거를 다시 봐야 하는지 알려 줌

장식 캐릭터가 아니라 **Quest NPC + 연구 책임자** 역할을 담당한다.

## 6.3 캐릭터 화면 점유 규칙

- 캐릭터는 핵심 학습 오브젝트를 가리지 않는다.
- 등장할 때 반드시 기능이 있어야 한다.
- 한 화면에서 두 캐릭터가 모두 필요하지 않으면 한 명만 사용 가능
- 대사는 1~2문장으로 짧게 유지
- 애니메이션은 학습 피드백을 보조하는 수준으로 제한

# 8. Mission 1~5 심화 설계

## Mission 01 — 초점을 되찾아라

| 항목 | 내용 |
|---|---|
| 학습목표 | 달의 전체 모양과 표면을 관찰하고 서로 다른 영역의 특징을 비교한다. |
| 퀘스트 상황 | 연구소 달 관측기가 흐릿한 영상만 보내고 있어 검증된 관측사진이 없다. |
| 학생 핵심 행동 | 망원경 시야 이동 → 확대 → 초점 조절 → 촬영 → 표면 영역 확대 → 비교 |
| 주요 상호작용 | Drag, Pinch Zoom, Circular Focus, Magnifier Drag, Tap |
| Micro Loop | 달 탐색 → 흐릿함 확인 → 배율·초점 수정 → 선명도 변화 → 촬영 → 영역 비교 |
| 실패/재시도 | 배율이 너무 높거나 초점이 맞지 않으면 영상 자체가 흐리게 유지된다. 즉시 조절 가능 |
| 과학적 피드백 | 정답 O/X 대신 달의 선명도와 관찰 가능한 표면 정보가 변한다. |
| 획득 Evidence | **달 표면 관측 기록** |
| World Change | 망원경 렌즈가 정상화되고 연구소 달 관측실 첫 조명이 켜진다. |
| 유지 | 망원경 포착, 핀치 확대, 표면 3지점 비교 |
| 개선 | 표면 특징을 먼저 알려 주지 않고 학생이 직접 관찰한 뒤 비교하도록 순서 변경 |

## Mission 02 — 끊긴 달빛 기록을 복원하라

- Research Kit 5/5

**천체 자체가 변화하는 것이 아니라 연구소의 관측·기록·분석 시스템이 학생 연구로 복구된다.**

# 13. NPC 변화

## 시작 — 별여우 연구관

## Mission 2 후

> “행성 자료가 다시 정리됐어. 하지만 별과 행성 분류 회로가 아직 근거 없이 판단하고 있어.”

## Mission 4 후
> “이제 분류기는 근거를 확인하고 있어. 마지막으로 북극성 주변 관측 지도를 복구하면 돼.”

## Mission 5 후
> “모든 관측 데이터가 모였어. 연구 결과를 중앙 관측실로 가져와 줘.”

## Final Report
> “다섯 기록이 모두 확인됐어. 이제 이 자료를 중앙 관측 코어에 직접 연결해야 해.”

## 엔딩
> “연구소가 다시 정확한 밤하늘을 기록하기 시작했어. 이건 네가 직접 관찰하고 검증한 결과야.”

달토끼 기록원은 각 Mission 완료 시 학생의 Evidence를 Research Kit에 저장하고 이전 관측자료를 다시 열어 주는 기능을 담당한다.

# 32. 참고 및 벤치마킹 원칙

본 심화안은 Science World 공통의 **Quest → Evidence → World Change → Final Report → Final Mission → Final Movie → Certificate** 구조를 적용한다.

첨부된 마스터 설계 원칙은 기존 설계를 폐기하는 용도가 아니라, 현재 「별빛 관측 연구소」의 5 Stage/10 Screen 구조를 유지하면서 게임성·재도전·학습 결과물·세계 변화·최종 성취감을 강화하는 기준으로 반영한다.

외부 수업자료와 기존 에듀테크 사례는 기능과 학습 흐름만 참고하며, 원본 UI·문항·캐릭터·게임 규칙을 복제하지 않는다.
